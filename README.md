# Mod App Filter

เว็บต้นแบบสำหรับปกปิดข้อมูลส่วนบุคคลก่อนส่งต่อให้ AI หรือระบบอื่นภายในองค์กร

## เริ่มต้น

ต้องใช้ Node.js 20.9 ขึ้นไป

```sh
npm install
npm run dev
```

เปิด http://localhost:3000 จากโฟลเดอร์หลัก `Mod App Filter` ได้เลย บน PowerShell ที่ปิดการรันสคริปต์ ให้ใช้ `npm.cmd` แทน `npm`

## เทคโนโลยี

Next.js App Router, TypeScript, Tailwind CSS v4 และ shadcn/ui โดยใช้ Radix UI สำหรับคอมโพเนนต์ที่มีพฤติกรรมโต้ตอบ

## ระบบ UI

- ใช้ดีไซน์จาก `suea-safety.md` เฉพาะเมนู ปุ่ม ตาราง และธีมสี: ฟ้า `#0B82F0`, พื้น `#EEF7FF`, ตัวอักษร `#0B2F6B`, ฟอนต์ Sarabun โดยเก็บสูตรที่เลือกไว้ใน `lib/suea-safety.ts`
- Desktop ใช้เมนูบนพื้นขาวและ gradient สำหรับเมนู active; หน้าจอแคบกว่า 1200px มี bottom nav 4 รายการจากเมนูจริง พร้อม safe-area และพื้นที่เผื่อด้านล่าง ส่วนเมนูเพิ่มเติมยังเปิดได้จากปุ่มเมนูด้านบน
- การเข้าสู่ระบบ การปกปิดข้อมูล และการตรวจบทบาท User/Admin ใช้การทำงานเดิม ไม่มีการเพิ่ม Coin, Leaderboard หรือระบบ Gamification จากตัวอย่าง
- ทุกหน้าใช้คอมโพเนนต์ร่วมจาก `components/ui`: Button, Input, Textarea, Label, NativeSelect, Card, Badge, Table, Switch, Dialog และ DropdownMenu
- Layout, สี, spacing, responsive และ interaction states ใช้ Tailwind utilities โดยเก็บสูตรสไตล์ของดีไซน์เดิมไว้ใน `lib/ui-styles.ts` และ `app/login/login.styles.ts`
- `ui('ชื่อสูตร')` รวม utility classes และจัดการคลาสที่ทับกันด้วย `tailwind-merge` ชื่อสูตรยังเป็น hook สำหรับ descendant/state variants ไม่มีการสร้าง CSS ตอน runtime
- พื้นฐาน theme, typography และ keyframes อยู่ใน `app/globals.css` ไม่ใช้ไฟล์ CSS แยกของหน้าเดิมหรือ CSS Modules
- คอมโพเนนต์รองรับสไตล์มาตรฐานของ shadcn และตัวเลือก `unstyled` สำหรับส่วนที่ส่ง utility recipe ของดีไซน์โปรเจกต์ให้โดยตรง
- เพิ่มส่วนใหม่ด้วยคอมโพเนนต์ใน `components/ui` และ Tailwind classes; ใช้ semantic theme tokens เช่น `bg-card`, `text-foreground`, `border-input` และ `ring-ring` ให้สอดคล้องกัน

## ฟีเจอร์ที่ลองได้

- วางข้อความและอัปโหลดไฟล์ TXT, CSV, JSON, Markdown แบบ UTF-8 ขนาดไม่เกิน 5 MB
- ปกปิดชื่อที่มีป้ายกำกับหรือคำนำหน้า เลขบัตรประชาชน อีเมล เบอร์โทรไทย และคำที่กำหนดเอง
- เลือกปกปิดทั้งหมด เหลือท้าย 3 ตัวอักษร หรือแทนด้วยประเภท
- ดูผลลัพธ์ คัดลอก และดาวน์โหลดกลับเป็นไฟล์ชนิดเดิม
- ตั้งค่านโยบายและดูประวัติในหน่วยความจำของแท็บปัจจุบัน
- หน้าเอกสาร API และตั้งค่าการเชื่อมต่อ Supabase แบบต้นแบบ
- มาสคอตมดจากภาพที่ผู้ใช้แนบ พร้อมธีมน้ำเงิน–ครีม–ส้ม แอนิเมชัน และตัวอย่างก่อน–หลังที่กดลองได้
- โหมดเปรียบเทียบต้นฉบับกับผลลัพธ์

ข้อมูลประมวลผลในเบราว์เซอร์ ไม่บันทึกเนื้อหาลง localStorage หรือฐานข้อมูล และประวัติหายเมื่อรีเฟรช

## ขอบเขตของต้นแบบ

ยังไม่เชื่อม Supabase, ระบบสมาชิก/สิทธิ์, API จริง, OCR, PDF หรือ DOCX การตรวจจับใช้กฎ ไม่ใช่ NER ชื่อที่ไม่มีป้ายกำกับอาจตรวจไม่พบ ต้องตรวจผลลัพธ์ก่อนส่งต่อ การซ่อนบางส่วนยังเหลือข้อมูลท้ายตามรูปแบบที่เลือก ไฟล์ JSON/CSV จะปกปิดจากข้อความดิบโดยรักษาเครื่องหมายคั่นไว้ ควรตรวจสอบโครงสร้างและความหมายก่อนใช้งานจริง

ชื่อ API host และ API key ในหน้าคู่มือเป็น placeholder ไม่ใช่บริการที่เปิดใช้งานแล้ว

เตรียมเชื่อม Supabase ภายหลัง: Auth + organization membership, masking policies, metadata-only audit events และ API keys แบบ hash พร้อม RLS โดยไม่เก็บข้อมูลต้นฉบับเป็นค่าเริ่มต้น

## Login และ Admin แบบ mockup

- `/login` หน้าเข้าสู่ระบบ เลือก User หรือ Admin แล้วใช้ข้อมูลตัวอย่างที่กรอกไว้ได้เลย
- ตัวอย่าง User: `member@example.com` / `demo1234` และ Admin: `admin@example.com` / `demo1234`
- แบบฟอร์มยอมรับอีเมลที่มีรูปแบบถูกต้องกับรหัสผ่านจำลองอย่างน้อย 6 ตัวอักษร ไม่ตรวจสอบหรือจัดเก็บรหัสผ่าน
- `/` ส่งต่อไป `/home` และ `/admin` หน้าผู้ดูแลระบบ จำลองการจำกัดหน้าตามบทบาท
- โปรไฟล์และบทบาทจำลองเก็บใน sessionStorage ของแท็บปัจจุบัน ออกจากระบบเพื่อล้างเซสชัน
- Admin ทดลองเพิ่ม/นำสมาชิกออก ค้นหา เปลี่ยนบทบาท เปิด–ปิดสถานะ ตั้งค่านโยบาย ดูและส่งออกบันทึกกิจกรรมเป็น JSON ได้
- สมาชิก นโยบาย และบันทึกกิจกรรม Admin เป็นข้อมูลตัวอย่างในหน่วยความจำ คงอยู่เมื่อสลับเมนู Admin และจะรีเซ็ตเมื่อออกจากส่วน Admin หรือโหลดใหม่ ไม่มีการสร้างบัญชีหรือส่งอีเมล
- นโยบายของ Admin ยังไม่บังคับใช้กับตัวปกปิดข้อมูล นี่เป็นการจำลอง UI เท่านั้น ไม่มี server authentication หรือ authorization ต้องเชื่อม Supabase Auth และบังคับสิทธิ์ฝั่ง server/RLS ก่อนใช้งานจริง

## เส้นทางของแต่ละเมนู

แต่ละเมนูมีไฟล์ `page.tsx` และ URL ของตัวเอง ใช้ Next.js Link สำหรับเมนูบนเดสก์ท็อปและมือถือ รองรับการเปิดลิงก์ในแท็บใหม่ การรีเฟรชหน้าตรง และปุ่มย้อนกลับ/ถัดไปของเบราว์เซอร์

| URL | หน้า |
| --- | --- |
| `/home` | พื้นที่ปกปิดข้อมูล |
| `/history` | ประวัติการใช้งาน |
| `/policies` | นโยบายการปกปิด |
| `/api` | คู่มือ API และการเชื่อมต่อ |
| `/settings` | ตั้งค่าพื้นที่ทำงาน |
| `/admin` | ภาพรวมผู้ดูแลระบบ |
| `/admin/members` | จัดการสมาชิก |
| `/admin/policies` | นโยบายขององค์กร |
| `/admin/activity` | บันทึกกิจกรรม |

`app/(workspace)/layout.tsx` และ `app/admin/layout.tsx` ใช้เมนูและ state ร่วมภายในแต่ละส่วน โดยแยกเนื้อหาหน้าไว้ใน `components/workspace/*-view.tsx` และ `components/admin/*-view.tsx` ตามลำดับ ข้อความ ผลปกปิด ประวัติ และนโยบายยังอยู่เมื่อสลับเมนูผ่านแอป ข้อมูลในหน่วยความจำยังรีเซ็ตเมื่อรีเฟรชเหมือนเดิม

โปรเจกต์ใช้ static export ดังนั้น `/` ส่งต่อไป `/home` ฝั่งเบราว์เซอร์ ไฟล์ HTML ของทุกเส้นทางถูกสร้างใน `out/` เมื่อ build และ static server ต้องรองรับการจับคู่ `/history` กับ `/history.html` เช่นเดียวกับเส้นทางอื่น ๆ
"# Mod-App-Filter"
